   │                         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   │ RSA-based JWT/JOSE algorithm is broken by Shor's algorithm
   = why: A JWT or JOSE object is signed (RS256/384/512, PS256/384/512) or encrypted
          (RSA-OAEP, RSA1_5) with RSA. Shor's algorithm recovers the RSA private key
          from the public key, which is usually published in a JWKS endpoint: anyone
          could then mint valid tokens for your users, and encrypted tokens recorded
          today could be opened later.
   = help: Plan the move to post-quantum JOSE algorithms: ML-DSA (FIPS 204) for token
           signatures, as being standardized for JOSE by the IETF COSE working group,
           and ML-KEM (FIPS 203) for encrypted tokens. Tokens are short-lived, so the
           urgent part is the signing key and the verifiers: make them algorithm-agile
           (publish several keys in the JWKS, pin the accepted algorithms per key) so
           issuers can switch without a flag day. RSA1_5 should be removed today
           regardless; it is vulnerable to padding-oracle attacks.
   = ref: https://csrc.nist.gov/pubs/fips/204/final
